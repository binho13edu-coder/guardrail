# Sponsorship and sustainability plan

GuardRail is maintained as a public-good security tool. The project accepts voluntary financial support to make maintenance predictable without putting core security checks behind a paywall.

## How to support

GitHub Sponsors is the first channel because it keeps identity, payment, and repository context in one place. The repository includes `.github/FUNDING.yml`; the Sponsor button becomes active after the maintainer completes GitHub's enrollment and payout setup. No payment account or financial transaction is created by this repository change.

For organizations, a future sponsorship agreement may fund a clearly scoped roadmap item. Any such work must remain available under the project's open-source license and must be disclosed in the changelog.

## Suggested support levels

These are planning tiers, not a promise of service:

- **Community supporter:** helps cover CI, dependencies, and documentation.
- **Maintainer supporter:** helps reserve recurring time for issue triage, releases, and reviews.
- **Organization supporter:** helps fund a public roadmap item such as Kubernetes policy coverage or SARIF improvements.

Support does not provide a security exception, a guaranteed response time, private access to fixes, or priority over responsible-disclosure reports. Security reports continue to follow [SECURITY.md](../SECURITY.md).

## Use of funds

The target allocation is:

1. CI runners, package/tooling costs, and dependency maintenance.
2. Security triage, reproducible fixtures, and release hardening.
3. Documentation, examples, contributor experience, and community support.
4. A reserve for incident response and unexpected infrastructure costs.

No sponsor payment should influence the severity, publication timeline, or remediation decision for a vulnerability.

## Transparency and governance

The maintainer will publish a short quarterly update in the changelog or a GitHub Discussion covering funded work, major maintenance outcomes, and the next priorities. Updates will use aggregate amounts only; sponsor identity and payment details will never be committed to the repository.

The roadmap remains community-driven. Sponsored proposals are evaluated using the same security, maintainability, and scope criteria as unfunded proposals, and acceptance is never guaranteed.

## Success measures

The program will be reviewed against practical outcomes: time to first issue response, release cadence, CI reliability, dependency update age, security-fix lead time, and the number of active contributors. If support does not improve these outcomes, the model will be revised publicly.
